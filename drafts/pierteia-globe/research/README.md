# 美术调研与 v10 问题审计

复核日期：**2026-10-15**。起点：`0f7f1ae`。本轮不是第十一版画面发布。

用户反复指出“廉价、粗糙”是成立的反馈。以前把结构数量、材质类型、分辨率和浏览器测试当成进展，却没有建立令人信服的视觉基准；本轮停止在同一套外观上继续零碎加料，先核对参考、比例和制作方法。

**已做：**逐项核对用户给出的工具/资料，读取相关一手文档和案例，查看4张建筑参考照片，审计当前源码并运行尺度测量。**未做：**没有完整观看所有示例视频，没有安装全部推荐工具，没有换上扫描材质，没有完成新的场景样板，也没有据此宣布美术问题已解决。

## 1. 不再靠感觉判断的具体问题

可执行记录：[v10-scale-audit.json](v10-scale-audit.json)。运行 `node tools/audit-art-scale.mjs` 可复核。

以当前以米建模的Blender资产、网页 `scale=.01` 为相对标尺：

| 项目 | 实测 | 为什么影响观感 |
|---|---:|---|
| 占位人物模型本体 | **0.40米** | 不是正常成人比例；在门、桌椅旁像小摆件。模型顶部距放置平面0.46米，不能把这两个数混说 |
| 图书馆近景相机距其脚下地形 | **12.08米** | 名为近景，仍是明显的高机位 |
| 教学楼 / 工坊近景 | **8.90 / 8.89米** | 难以建立人的空间体验 |
| 阅览室“street” / 材质机位 | **6.40 / 3.90米** | 适合某些细节观察，但不能代替人眼尺度机位 |

这是**渲染资产之间的相对单位审计**，不是世界观新增测绘数据。地形高度没有计入架空平台或楼板，不能把表中数值直接当成相机离最近可站立表面的距离。高机位本身没有错，错在缺少另一组真正接地的观察方式。1.70米是假人校准目标，不是在改正式角色身高。

另有已定位的实现/设计问题：

- `world-finish.js` 会清空屋面的颜色贴图，以及地表的颜色、法线和粗糙度贴图。于是“加载了PBR资源”不等于最终表面使用了那套资源；当前地面主要依靠程序噪声。
- `roof-detail.js` 的逐瓦色差、微弧和外露下唇没有先用实物尺度对标；实体瓦片依然可能像厚积木。必须对比瓦的长宽、有效搭接长度、边缘厚度，而不是只确认“每片都建了”。
- `vegetation.js` 虽然不再使用旧交叉叶片，但真实树种的枝序、冠幅、疏密和近景树皮仍未建立；“独立叶片”也不是质量保证。
- 图书馆所有开间都几乎同等强调窗框和书架，缺少安静墙面、主入口与阅读空间的主次。不能继续把书本当橱窗陈列一样整面铺满。
- 同一套泛光、环境照明、太阳和遮蔽不能代替逐场景的明暗设计。GTAO是遮蔽近似，不是墙下、檐下和室内的真实间接光。
- 先做一个中景、一个人眼视角和一个材质近景，相同资产、曝光和光照一起看；不再只挑唯一好看的镜头。

## 3. 补充的一手依据与制作案例

### 建筑画面与材料

[Maxon：Architectural Rendering Techniques（2026）](https://www.maxon.net/en/article/architectural-rendering-techniques)把构图、相机、光照层次放在采样数之前，讨论了实物比例、粗糙度分层、尺度参照、成组布景与受控磨损。它有产品推广语境，本项目只借鉴可验证的方法，不把购买某个渲染器等同画质保证。

**采用：**真实尺度与稳定光照先过关；同一材料在正面、斜光和近景下都成立。噪点、辉光和景深不能遮掩失败。

### 环境艺术家的做法

- [Franek Leszczynski：Fisherman House，2025-09-24](https://80.lv/articles/building-moody-coastal-fisherman-cabin-scene-in-ue5)：先锁构图和资产清单，模块木板、可平铺材质与RGB遮罩分工，细节需要时才雕刻/烘焙。迁移到本项目的是**材质主层—遮罩变化—局部污损**，不是复制房屋、概念图或夜景配色；文中Unreal/Nanite能力也不能说成网页已有功能。
- [Evgenia Greciano：林地木屋，2025-06-11](https://80.lv/articles/creating-immersive-forest-cabin-environment-inspired-by-alan-wake-2)：先选同一环境体系的树、地被、土壤参考，贴图尺度反过来约束瓦片几何，关键树人工放置。采用**同一生态与施工逻辑**，不再随机撒同一种树和白石。

两篇是制作访谈，不是性能基准；嵌入视频没有全程观看，文章图片不可当免费贴图或模型使用。

### PBR校验

- [Filament材质文档](https://github.com/google/filament/blob/cfb8e32833013d8531e64f2bfccfe8ce815797ff/docs/Materials.md.html)：区分介质与金属、颜色与数据通道、粗糙度、反射率和AO。尤其不能把Filament的`reflectance=.5`照抄成Three的`metalness=.5`；参数语义不同。
- [Khronos glTF Sample Viewer](https://github.com/KhronosGroup/glTF-Sample-Viewer)：可分通道查看并调整参考照明，也有验证入口。下一样板的同一GLB需要在参考查看器与本项目都检查，区分资产本身的问题与运行时覆盖材质的问题。本轮尚未完成双查看器对照。

## 5. 工具选择和当前版本的风险

截至本次检索，Three的GitHub最新release为r186，项目内仍为r170；CSM的仓库包为6.4.0，而GitHub`releases/latest`仍指向更旧的5.3.0。因此不能把单一“latest”字段当成安装决策。

| 工具/方法 | 决定 | 理由或前置条件 |
|---|---|---|
| Blender：真实尺度、UV、局部高模→法线/AO/光照烘焙 | 下一样板的主要资产工具 | 输出可交互GLB和可追溯贴图，不能用离线图片冒充互动模型 |
| 扫描PBR、校准HDRI | 先收集逐资产许可与物理覆盖尺寸 | 代码库许可不覆盖所有图片/模型；不默认Megascans或来源不明包可重分发 |
| Three标准/物理材质 + 有依据的环境光 | 先作为基线 | 去掉互相掩盖的临时颜色/强度修补；不再对全场景同时乱调 |
| CSM | 单独技术样板验证后再决定 | 保留现有光照的定制入口，兼容范围声明不是完整实测 |
| WebGPU / SSGI / 路径追踪 | 单独实验，不热替换整个地图 | 当前读到的Three SSGI示例和路径追踪器README主推的是WebGPU路径；现有r170 WebGL链路不是同一套。包内其他入口仍需另行核验 |
| p5.brush、See-through | 当前3D返工不引入 | 分别解决绘画/2.5D拆层，不解决建筑体积、比例与物理表面 |
| Remotion、XSXB-Band | 当前不引入 | 只有明确需要视频/音频交付时使用 |

许可核对：LYGIA当前README为Prosperity/Patron双许可；Remotion为带主体规模条件的许可，不是简单MIT。其他库也应固定实际采用版本再核查。此次**没有购买、安装付费软件或执行下载来的skills**。

## 6. 下一步不是全图再刷一版：先做可推翻的样板

采用的工作标准见 [../DESIGN.md](../DESIGN.md)。先做学院入口到阅读庭院的一段可自由绕看的三维样板：一面主体墙、一个真实开口、一段屋檐、铺地接坡、一棵近景树。范围少，但必须同时解决尺度、材料、光照和构图，而不是再做一块材质球就宣布成功。

1. 把米制参照、人眼机位、门/桌椅/栏杆放在同一空间核对，保留总览。
2. 先锁主次体量和阴影关系，再做细节；连廊不能挡住被称为“教学楼近景”的主体。
3. 灰泥、石基、木、金属、玻璃分别有参考、物理尺度和通道解释；增加一个真实材料基线，停止全部依赖现有程序噪声。
4. 固定同一机位与曝光，做材质/法线/粗糙度分离检查；将GLB在参考查看器核对。
5. 直接看网页普通分辨率中景、斜侧近景和人眼视角；静态成立后才整理镜头切换和次要环境动作。
6. 样板没有明显摆脱当前积木/微缩感就继续改，不扩展复制到八景。用户只评价实际画面，不承担技术选型。
