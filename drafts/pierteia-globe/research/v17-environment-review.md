## 实际实现

- **环境分离**：每景独立的天空渐变、云量与风向、雾色/距离、太阳色/强度、环境光和半球光。退出特写时恢复球体光照与无局部雾状态。
- **水体分离**：保留原有反射水面与深度场，新增逐景的深浅色、浪幅、泡沫量、风向、速度和太阳方向。璇玑不复用海港浪幅；汐见町降低局部水面时，船体在静态合批之前一同移到对应吃水位置。
- **材质不串景**：对共享 PBR 材质按场景克隆，明确保留原来的 `onBeforeCompile` 和程序缓存键。湿润区修改颜色与粗糙度，钢构的氧化区同时减弱金属响应；盐斑集中在低处立面，雪层依高度和朝上程度，不把所有屋顶/地表统一换色。原有纹理和木纹方向仍保留。
- **地表与植物**：新增按真实局部高度、坡度、建筑排除区布置的蕨状地被、芦草、滨岸草、低草甸及高处以下的草本；固定种子和 instancing。不在雪线以上撒同一套绿草，也不把水草撒到城市中央。
- **天气不是全屏滤镜**：雨线和雪点在三维场景中受深度遮挡；汐见町33个屋顶/摊棚代理区让雨在遮蔽物上方结束。代理是保守近似，并非逐滴物理碰撞。水面雨纹与雨雪/近地雾开关一起关闭。
- **可关闭**：开关位于可折叠介绍中，标签至少44px高。不额外占据默认手机取景区。关闭叠加仍保留阴天和湿材质，不把整个场景突然改成晴天。系统 `prefers-reduced-motion` 时关闭雨雪和近地雾叠加；既有动画循环仍负责暂停，不新增后台计时器。

## 实际目视查修

本轮先渲染汐见町、天神峰和璇玑试查，随后检查八景全景、学院山坡及四地建筑近景。

1. **天神峰外围花纹**：原来的背景平面与山地平坦边缘同高，发生深度冲突。降低背景平面后重新查看，消除了大面积交错闪纹；同时分开雪坡与裸岩，补局部山脊和融水沟。
2. **大陆场景方形截边**：原地面网格到边界就停，远处呈方形平台。保留前景原密度，另接低密度远景地表到雾区，没有通过减面前景来遮掩。
3. **湖岸芦草过少**：首轮只有6簇，因为原岸坡过陡，坡度筛选几乎全部排除。只放缓建筑区外的岸线，保留中央码头与建筑脚点；实际渲染有105簇。
4. **雨丝抢画面**：首轮线段过亮、过长；降低长度和透明度后重看，街道、屋顶和港口轮廓更清楚。
5. **界面截图时序**：测试脚本在展开介绍后暂停着渲染，旧帧不能用来判断相机避让。补上布局稳定后的真实帧，再保存展开状态。

## 技术核对

本轮通过 GitHub API 实际读取项目所用 Three r170 的：

- [Material.js](https://github.com/mrdoob/three.js/blob/r170/src/materials/Material.js)：`onBeforeCompile`、`customProgramCacheKey` 及复制行为。局部克隆后显式保留钩子链，不悄悄丢掉既有木作/地表着色。
- [Water.js](https://github.com/mrdoob/three.js/blob/r170/examples/jsm/objects/Water.js)：反射时隐藏自身、临时关闭阴影更新，以及色调映射/色彩空间/雾的输出顺序。新增参数保持项目现有反射流程，不升级 Three，也不额外下载资产。

这不是新一轮完整外部资料调研；此前资料来源和授权记录仍保留。没有引入新的外部贴图、模型或库。
